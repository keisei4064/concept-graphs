# 論文方式Scene Graph（Qwen版）の作業計画

作成日: 2026-10-26

状態: 計画作成。実装・追加推論・本実験は未着手。

## 1. 目的と合意事項

完成済みのroom0物体マップを使い、物体の観測画像を切り出すところから、
論文方式の後処理型Scene Graphを別実験として構築する。
フレーム全体の注釈画像から関係を取得する、現在の`ali-dev`リアルタイム経路とは区別する。

- Caption生成、物体単位の要約、物体ペアの関係推定は、すべてローカルQwenを使用する。
  第一候補は既存の`qwen3.5:35b`。モデルタグ・digest・推論設定を記録する。
- 保存済みの画像、マスク、2D BBox、confidence、3D物体を再利用する。
  YOLO・SAM・CLIP・逆投影・Association/Fusionは再実行しない。
- 既存のフレーム単位Captionや救済済み`description`を、新しい切り出し画像のCaptionとして流用しない。
- 観測選択、切り出し、物体の除外条件、MST、関係種別は参照コードの処理を維持する。
  変更はモデル・通信の置換、実行に必要な互換性修正、ID等の整合性修正、記録・表示に限定する。
- 既存のリアルタイム処理と成果物を置換しない。本実験は「同じ物体マップ上での方式比較」であり、
  モデルやマッピングまで含む論文全体の忠実再現とは呼ばない。

元の[CODEX_INSTRUCTIONS.md](CODEX_INSTRUCTIONS.md)は`ali-dev`再現を対象としていた。
本計画は、その経路を維持したまま、今回の会話で合意した別ルートを追加するための計画である。
今回依頼されている作業は計画書作成まで。実装・推論は後続の作業として区別する。

## 2. 入力と処理の境界

入力実験:
`outputs/local-only/assets/data/Replica/room0/exps/room0_reference_graph_attempt1/`

- 地図: `pcd_room0_reference_graph_attempt1.pkl.gz`
- 200入力画像、stride 10で完成した73物体。マップ内の対応検出は3805件。
- 物体の`color_path`、`mask`、`xyxy`、`conf`、観測履歴と点群・BBoxを使う。
- 元映像は`outputs/local-only/assets/data/Replica/room0/results/`にある。
- 既存比較対象は同実験の物体・エッジJSONと元のRGB付きRerun。

```text
完成済み73物体マップ＋観測履歴
  → 物体ごとにconfidence上位の最大10観測を選択
  → 各観測のRGB・マスク・2D BBoxから物体画像を切り出す
  → Qwenで各切り出し画像のCaptionを生成
  → Qwenで物体単位の説明・object_tagへ要約
  → 元の条件で無効物体・観測不足物体を除外
  → 幾何的重複グラフを作り、連結成分ごとにMSTを計算
  → MSTの候補ペアについて、説明＋3D BBoxをQwenへ渡して関係推定
  → 物体・候補・推定関係・出典を保存し、3D表示で比較
```

最終の関係推定は画像入力ではなく、物体の説明とBBoxの中心・寸法によるテキスト入力。
元映像番号、200枚中の処理フレーム番号、観測番号、元map物体ID、グラフ内IDは別々に保存する。

## 3. 参照処理と最小修正

主な参照元:

- [build_scenegraph_cfslam.py](../../conceptgraph/scenegraph/build_scenegraph_cfslam.py):
  観測選択、切り出し、Caption要約、物体の除外、MST、関係推定。
- [GPTPrompt.py](../../conceptgraph/scenegraph/GPTPrompt.py): 物体説明の要約プロンプト。
- [utils.py](../../conceptgraph/slam/utils.py): 現在の重複計算関数。
- [ollama_vlm.py](../../conceptgraph/utils/ollama_vlm.py)と
  [local_runtime.py](../../conceptgraph/utils/local_runtime.py): ローカル通信と実行制約。

| 箇所 | 方針 |
|---|---|
| 観測選択 | confidence降順、最大10観測。2観測未満を扱う条件も元の処理に従う |
| 切り出し | padding 10、元のmasking設定を明記。既定`none`を勝手に輪郭付きへ変えない。70×70未満の面積の画像を除く処理を維持 |
| Caption | 元の切り出し用プロンプトを基準にLLaVAをQwenへ置換。フレーム全体用プロンプトと混ぜない |
| 要約 | 元のプロンプトと`summary`・`possible_tags`・`object_tag`の契約を維持し、GPT-4をQwenへ置換 |
| 関係推定 | 元のプロンプトを基準にQwenへ置換。`reason`と`object_relation`を保存 |
| 関係種別 | `a on b`、`b on a`、`a in b`、`b in a`、`none of these`を維持。既存リアルタイム版の関係スキーマを流用しない |
| 重複関数の呼び出し | 現在の`compute_overlap_matrix_general(args, scene_map)`は引数契約と不整合。正しい物体引数と必要な距離引数を渡す形へ修正 |
| 重複指標・MSTの重み | P0で参照処理を確認し固定。呼び出しが動くだけで論文と一致したとは扱わない。最小を最大へ変える、重みを反転する等の独自変更はしない |
| ID整合性 | 元の物体除外方針を維持。応答リストの位置を元の物体IDと混同する箇所だけを修正し、元map ID・UUIDとの対応を保持 |
| 失敗応答 | 失敗と正当な`none of these`を区別。失敗を関係エッジにせず、途中欠落で後続ペアの応答がずれないようペアIDで管理 |

JSON形式の指定を追加する場合は、その追加部分を記録する。
Schemaを要求しただけで正常とせず、実際の返却フィールド・型・関係種別を検証する。
有効な結果は残し、失敗・除外・不足は対象物体またはペア単位で記録する。
モデルへ修正指示を繰り返す独自の再生成ループは既定で追加しない。

## 4. 作業手順と完了条件

### P0: 入力・参照仕様の固定（推論なし）

1. 入力地図、参照コード、設定をSHA256で固定する。Gitコマンドは使わない。
2. 73物体の観測パス・BBox・マスク・confidenceの対応と読み出しを確認する。
3. 切り出し用プロンプト、要約プロンプト、関係プロンプト、閾値・フィルタ条件を抽出する。
4. 重複指標、閾値、重複行列の方向性・対称化、MSTへ渡す重みを参照コード・原典に照合する。
   現在のコードにある引数不整合と、意図した指標の確認を分けて記録する。
5. 参照処理と修正箇所の対応表を作る。不明な挙動を推測で別アルゴリズムへ置き換えない。

完了条件: 入力manifestと処理仕様が固定され、未確定の指標・重みを残さずP1以降へ進める。

### P1: 観測選択・切り出し・ID対応（推論なし）

1. 元の選択条件で観測を選び、画像・マスク・BBoxの対応を保持して切り出す。
2. 各画像に元map ID、UUID、観測番号、元画像、confidence、切り出し座標、SHA256を付ける。
3. 切り出し例をコンタクトシートで確認する。小画像・観測不足・読込失敗の扱いを別々に集計する。
4. 元map IDからグラフ内IDへの対応を、物体の除外後も保持する。

完了条件: 全物体の選択・除外理由が追跡でき、代表例の切り出しが対象物体と一致する。
元画像の欠損やマスクの対応不良を、黙って別の観測へ差し替えない。

### P2: Qwen接続と小規模試験

1. ローカル通信部分を再利用し、切り出しCaption・物体要約・ペア関係の3契約を用意する。
   既存リアルタイム版のプロンプト・パーサ・Schemaは変更しない。
2. 3〜5物体、各最大3観測を明示的なpilot設定で試す。これは本実験の最大10観測設定とは分ける。
3. 最終マップから得た候補ペアの少数を使い、関係推定まで実モデルで通す。
   候補がない場合、テスト用ペアとMST由来のペアを区別して記録する。
4. 元応答、実際の入力画像、プロンプト、Schema、採用結果、失敗理由、遅延、モデル情報を保存する。
5. クライアントと一時Ollamaの通信先、実際のフィールド、Caption内容、関係の方向を確認する。

完了条件: 3タスクの正常応答が実モデルで確認でき、異常応答も追跡できる。
速度・VRAM・保存容量を実測し、全体実行の見積もりを出せる。少数試験だけで精度を主張しない。

### P3: MST・関係推定・保存の結合

1. 保存された要約と元の除外条件から対象物体を確定する。
2. 固定した幾何的重複グラフとMSTから候補ペアを列挙し、推論前に保存する。
3. 各ペアをQwenへ渡し、向き・関係種別・理由を保存する。
4. `none of these`と失敗を除いた関係をグラフへ反映する。
5. キャッシュと段階保存を使い、再開時は成功済みの画像・物体・ペアの推論を繰り返さない。

完了条件: 全物体・候補・関係のID参照が有効で、保存物を再ロードできる。
推論失敗によって応答と候補の対応がずれない。関係0本でも件数を偽らず、実行完了と意味的評価を分ける。

### P4: 可視化・方式比較

1. 最終3D物体マップと新しい関係を、別のRerun記録として表示する。
2. 選択物体の切り出し画像・Caption・要約、選択ペアの入力・理由を参照できる一覧を用意する。
3. 元map ID・UUIDを使い、リアルタイム版との候補数・関係数・方向・関係の種類を比較する。
4. `on`系は向きを正規化して比較する。リアルタイム版にない`in`系を、単なる不一致として集計しない。

完了条件: 3D上の関係から根拠画像・説明へ辿れる。最終グラフは静的な後処理結果であり、
各フレーム時点で得られた関係のようには表示しない。
元RGB付きRerunはそのまま残す。Captionパネル等は既存記録に元からある機能と混同しない。

## 5. 実装・成果物の置き場所（予定）

実装は元スクリプトを比較用に保持し、小さい別入口と処理モジュールを追加する方針。

- `scripts/local_only/run_paper_scenegraph.py`: 段階実行・再開用CLI。
- `conceptgraph/scenegraph/local_paper_scenegraph.py`: 参照処理に沿う後処理とQwen接続。
- `tests/local_only/test_paper_scenegraph.py`: ID・候補・応答契約等の必要な検証。
- 本計画書、実行時の`RUNBOOK.md`、比較結果の`RESULTS.md`。

出力先の予定: `outputs/local-only/paper_scenegraph_room0/attempt1/`

```text
manifest.json                 入力・コードのハッシュ、モデル、設定、比較条件
observations.json             物体ごとの選択観測と選択・除外理由
crops/                        実際にQwenへ送る切り出し画像
captions.jsonl                切り出し画像ごとのCaptionと出典
object_summaries.jsonl        元物体IDを持つ要約・object_tag
id_mapping.json               元map ID・UUID・グラフ内IDの対応
overlap_matrix.npz            MST前の重複行列
candidate_pairs.json          連結成分・MST・関係推定対象ペア
relations.jsonl               ペアごとの元出力、採否、関係、理由、失敗
scene_graph.json              最終ノード・エッジ
vlm_cache/                    入力・プロンプト・元応答・採用結果・遅延
viewer.rrd                    新しい静的グラフの表示用記録
report.json / report.md       件数、失敗、時間、容量、方式比較
logs/                         進捗・実行状態・通信監査
```

ファイル名は実装時に整理してよいが、入力→観測→物体→候補ペア→推定関係の出典を失わないこと。
キャッシュキーには入力、プロンプト、モデルdigest、推論設定を含め、既存のフレームVLMキャッシュとは分ける。
保存地図は圧縮サイズに比べ観測マスクの展開が大きいため、不要な深いコピーや地図全体の重複保存を避ける。

## 6. 検証と規模の見積もり

必要な検証:

- 元物体IDが非連続、先頭・途中の応答が欠落、観測不足物体が除外される場合も対応がずれない。
- 各MSTの端点が対象物体に含まれ、自己ループがなく、連結成分ごとの辺数が妥当。
- `a on b`と`b on a`、`a in b`と`b in a`の表示方向が正しい。
- 不正JSON・未知の関係種別・タイムアウトが、エッジや正常キャッシュに混入しない。
- Schemaと異なる返却フィールドを実際の応答で検出し、欠落を正常成功として扱わない。
- 保存・再ロード、途中再開、元成果物のハッシュ不変、ローカル通信を確認する。

73物体をそのまま対象にできる場合の上限目安:

| タスク | 件数の上限目安 |
|---|---:|
| 切り出し画像のCaption | 73×10 = 730回 |
| 物体単位の要約 | 73回 |
| MST候補の関係推定 | 最大72回。対象物体数をN、連結成分数をCとするとN−C回 |
| 合計 | 最大875回。除外・小画像・既存の同条件キャッシュで減少 |

既存のフレーム全体Captionの遅延を、そのまま切り出し画像やテキスト推論の遅延には使わない。
P2のタスク別実測から残件数・終了見込み・保存容量を算出する。
全体実行へ進む判断は、その見積もりを示した段階で行う。計画書作成だけで長時間ジョブを起動しない。

## 7. 継続する制約

- Git操作は行わない。既存の2000枚ジョブを再開しない。元地図・画像・キャッシュ・RRDを上書き・削除しない。
- 既存の専用Conda環境とダウンロード済みQwenを使用し、ホスト環境や既存Ollamaサービスを変更しない。
- 推論はクラウド無効の一時Ollamaとループバック通信のみ。外部推論・モデル再ダウンロードは行わない。
- 完了報告では「互換性修正」「ID等の不具合修正」「モデル置換」「原方式からの差」を別々に記録する。
