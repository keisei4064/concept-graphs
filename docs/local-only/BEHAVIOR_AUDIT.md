# 原実装との挙動差と修正状況

更新日: 2026-10-26

比較対象は`ali-dev`のリアルタイム経路。論文のMST方式とは区別する。
修正前の指摘と修正後の挙動を以下に集約する。

## 比較範囲と証拠

- 起点`keisei4064/concept-graphs`の取得時点の`ali-dev`を読み取り専用で参照。
- Python・YAML・語彙・setupの計103対象を監査。既存95対象中88が同一、7が変更、新規8対象。
- 主要16ファイルは公式`concept-graphs/concept-graphs`の`ali-dev`とも同一だった。
- 元の起点コミットを履歴から抽出した比較ではなく、取得時点の内容との比較。
- ソース・SHA256・差分は`outputs/local-only/source_audit_20261026/`に保存。
  `upstream_ali_dev/`が起点fork、`official_ali_dev/`が公式主要16対象、`current/`が修正前の点検時ソース。
  `comparison.json`と`analysis.json`が比較結果。ファイル数はこの監査時点の値。

## 修正済みの意図しない差

| 修正前の差 | 現在の挙動 |
|---|---|
| VLMの解析・API・項目違反で全体停止 | 通常のAPI/解析失敗は応答単位で記録。不正項目は除外し、有効な項目を保持 |
| Captionの全ID必須・検出名完全一致 | 名前訂正・部分応答を許容。欠落は既存の`filter_captions`でnull補完 |
| 独自のタスクプロンプト | 元の3プロンプトとuser queryを再利用。JSON受け渡し形式の指定だけ追加 |
| 正常な重複関係の拒否 | 元と同様に保持。Captionの重複IDも既存のlast-winsを維持 |
| 初期フレームでの関係追加 | 元と同様、物体登録後は次フレームへ進み、関係は採用しない |
| 1回観測の関係も表示 | 既定を元の2回以上へ戻した。1回表示は明示的なoverride |
| 通常設定のstride 1 | 全区間stride 10。全2000枚stride 1は明示的な別設定 |
| 3D対応範囲外の例外化 | 理由をログに残して当該関係をスキップ |
| 空の証拠でCaption統合を呼ばない | 元と同様に呼び出し、空の統合結果は品質集計で区別 |

通常モードは`vlm.response_policy=upstream`、検証による自動再生成は0回。
元のPython-list形式も受け付ける。旧来の厳格な検証・再生成は、明示的な`strict`診断モードに保持。
通常処理と診断処理はそれぞれ`_request_upstream`と`_request_strict`へ分離している。

## 維持するローカル差分

### 接続と応答記録

- GPT系モデルをローカルQwenへ置換。ループバック固定・クラウド無効・通信監査を追加。
- 外部URL、禁止通信、redirect、入力ファイル等の異常は継続対象にしない。
- VLMに渡していないIDは早期に記録・除外する。元の後段で扱う3D対応可能なID集合とは、常に一致するとは限らない。
- JSON化と一部の不正項目フィルタは追加処理。完全な出力一致は主張しない。
- `description`→`caption`の救済は別のオフラインexportのみ。通常のパーサへ別名受理を追加していない。
- `completed_with_vlm_issues`と`completed`を区別。空の関係グラフも問題として報告する。

### 起動・ID・戻り値の整合性

以下は数式の変更ではないが、端点や件数が変わり得る修正として記録する。

- `MapObjectList(device=...)`の未対応引数を除去。
- 幾何フィルタ後の検出IDとマッチング配列indexを対応付け。
- 新規追加前の物体数をエッジのindex計算へ渡す。
- エッジ内部属性を実際の`obj1_idx/obj2_idx`へ修正し、全物体除外時にも参照を更新。
- merge後の物体一覧を先に参照先へ設定し、その後UUIDを読むエッジindex更新を実行。
- VLM無効時・早期return時の`merge_objects`の戻り値を呼び出し側と整合。
- 注釈文字が画像外に切れないよう表示位置を制限。VLM入力のピクセルは変わる。
- 空の検出・空のVLM対象を処理。非空のCLIP計算本体は維持。

既存マップ物体同士の統合で、消えた物体を端点に持つエッジを捨てる挙動は公式`ali-dev`にもある。
`merge_overlap_objects`と`merge_update_indices`の処理は公式と一致。
ローカル修正は更新時に参照する物体一覧の順序等であり、エッジの統合先への引き継ぎを追加していない。

### 保存・実行管理

- 完全なraw検出キャッシュをフレーム単位で認識し、部分キャッシュを再利用。
- 検出・地図を原子的に保存し、地図とエッジのシリアライズで重複コピーを抑制。
- supervisor、進捗・資源記録、保存物の再ロード検証、元RGB付きRerunの確認を追加。
- 再実行はキャッシュを再利用して3D融合を先頭から再計算する。融合途中からの直接再開ではない。
- per-frameの巨大な地図pkl複製を既定で無効化。時系列の表示記録は元RRDへ保存。

## 維持を確認した計算と検証

監査では幾何・マッチング・融合等11項目をAST比較した。
深度→点群・座標変換・幾何/視覚類似度・マッチング・融合、非空CLIPの前処理、
YOLO-World/SAM/OpenCLIPの指定、ScanNet200語彙、3D側の閾値と後処理間隔を維持。
Caption統合に先頭20観測を使う制限も元からある。

修正時の検証は単体テスト61件と、保存済みRGB-D/CLIP/応答によるCPUの1/3フレーム結合試験。
解析失敗、Caption欠落、名前訂正を注入し、保存・再ロード・参照整合性・通信監査を確認した。
証拠: `outputs/local-only/alignment_validation/`。この結合試験自体は新しいQwen推論ではない。

その後、Qwen35Bでstride 10・200枚を実走し、73物体・39関係を保存・検証した。
状態は`completed_with_vlm_issues`。Captionの返却キー不一致等があり、意味的正確性の合格ではない。
件数・出力先は[RESULTS.md](RESULTS.md)、実行法とログの意味は[RUNBOOK.md](RUNBOOK.md)を参照。

モデル置換、JSON形式、入力密度、依存バージョン、乱数等の差があるため、
ソースの計算本体の一致から、論文・デモとの数値結果の一致や精度を結論しない。
